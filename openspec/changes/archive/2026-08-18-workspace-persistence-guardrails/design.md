## Context

ここまでの change でアプリは機能するが、再起動でタブが消え、タブが増えればメモリを食い、「今どのアカウントを見ているか」が視覚的に弱い。日常運用に載せるために必要な仕上げをまとめて入れる。

この change には性質の異なる4つの能力が入るが、いずれも「常用可能にする」という単一の目的に紐づいており、個別に分けても検証単位として意味を成さないため1つの change にまとめる。

とりわけ**ガードレール（アカウント色の常時可視化）はマルチアカウント運用で実用上もっとも効く機能**であり、この change の中心に置く。

## Goals / Non-Goals

**Goals:**

- 再起動をまたいでタブ構成が保たれ、かつ起動が速い
- 多数タブを開いても実用的なメモリ消費に収まる
- 現在のアカウントが常に視界の端に入る状態を作り、prod 誤操作を物理的に見えるようにする
- ダウンロードがアカウント別に整理される
- キーボードだけで日常操作が完結する

**Non-Goals:**

- **メモリ使用量の削減そのもの**。AWSコンソールは重量級SPAであり、UIを削っても消費メモリはほぼ変わらない。ハイバネートは「多数タブを開いたまま常用できる」ためのものであって、本アプリが軽量になるわけではない
- ブックマーク同期、履歴管理などの汎用ブラウザ機能
- タブのグルーピング・ピン留めなどの高度なタブ管理

## Decisions

### D1: 起動時は全タブをハイバネート状態で復元する

30タブ保存されている状態で起動時に全部ロードすると、起動に数十秒かかり AWS への同時リクエストも大量に発生する。

**起動時は `webContents` を1つも生成しない。** URL / タイトル / favicon だけでサイドパネルのタブセクションを描画し、選択されたタブだけをロードする。これにより起動は一瞬で終わる。

この方式が成立するのは、**コンソールセッションが Cookie 側（パーティション）にあるため、復元が単なる再読込で済む**からである。セッション状態をアプリ側で持つ設計だったらこうはいかない。

### D2: ハイバネートは `webContents` の破棄、タブは残す

30分（設定可）非アクティブなタブは `webContents` を破棄し、URL / タイトル / favicon のみ保持する。タブ自体はタブセクションに残り、再選択で再ナビゲートされる。

`electron-app-shell` のタブ切替（`removeChildView()` によるデタッチ）とは別の概念である。デタッチは即座に戻せる非表示、ハイバネートはメモリを解放する破棄。`TabManager` はこの2つの状態を区別して持つ。

### D3: アカウントあたり10タブ超過で古い順に自動ハイバネート

上限に達したらタブを閉じるのではなくハイバネートする。閉じてしまうと利用者が開いていた作業が失われるが、ハイバネートなら再選択で戻せる。

### D4: 色バーは preload から `document.documentElement` の上端6pxとして注入する

アカウント色を「常に視界の端に入る」形で出すには、コンソールのページ自体に描くのが確実である。アプリのクローム（サイドパネル）だけに頼ると、**パネルを折りたたんだ瞬間にガードレールが消える**。`electron-app-shell` の D9 で折りたたみを必須要件にした以上、コンテンツ側の色バーは省略できない。

上端6pxという寸法は、コンソールのレイアウトを壊さず、かつ周辺視野で認識できる下限として選ぶ。

コンソールはSPAでページ遷移してもリロードされないため、注入は一度で足りない可能性がある。DOM の変化を監視して再注入する。

### D5: 色は左サイドパネル・タイトルバーにも反映する

色バー（コンテンツ側）とアプリクローム側の両方に出すことで、どちらを見ていても現在のアカウントがわかる。`prod` タグのアカウントはさらにタブに警告アイコンを追加する。

サイドパネル側は**左端のアクセント**として出す。左配置（`electron-app-shell` D9）により、色が細いラインではなくパネル1辺の面として常時視界に入るため、水平タブバー時代より強いガードレールになる。

### D6: ダウンロードは `~/Downloads/AWS/<accountAlias>/` へ自動振り分け

アカウントを跨いで作業すると、`~/Downloads` に `credentials.csv` が複数溜まってどれがどのアカウントのものか分からなくなる。アカウント別ディレクトリに自動で振り分ける。保存先ダイアログは出さない（毎回選ぶのは摩擦になる）。

同名ファイルは上書きせず一意な名前を付ける。認証情報CSVを上書きで失うと再発行が必要になる。

### D7: 設定は平文 `config.json` / `tabs.json` に置く

アカウント設定（色・タグ・既定リージョン）とタブ状態は秘密情報を含まないため、暗号化しない。デバッグ時に読めることの利点が上回る。

`electron-app-shell` の Open Question として残していた**サイドパネルの折りたたみ状態と幅も `config.json` に永続化する**。再起動のたびに幅を調整し直すのは日常運用の摩擦になる。

**ただし `tabs.json` に SigninToken を含む URL を保存してはならない。** federation URL は15分ワンショットであり保存する意味がなく、保存すれば秘密情報の平文保存になる。保存するのはナビゲート後の実 URL である。

### D8: ショートカットは単一レジストリで管理する

`Cmd+Shift+A`（`sso-account-directory`）、`Cmd+Shift+T`（`builtin-totp`）、サイドパネルの折りたたみ（`electron-app-shell` D9 で割当を本 change に委ねた）を含め、アプリ全体のショートカットが複数の change に分散している。重複割当を防ぐため、この change で単一のレジストリに集約する。

サイドパネルの折りたたみは **`Cmd+B`** を割り当てる。既存の割当（`Cmd+K` / `Cmd+T` / `Cmd+W` / `Cmd+1`〜`9` / `Cmd+R` / `Cmd+F` / `Cmd+Shift+[` / `]` / `Cmd+Shift+A` / `Cmd+Shift+T` / `Cmd+Opt+R` / `Cmd+Opt+I`）と衝突せず、サイドバー開閉として一般的な割当である。

## Risks / Trade-offs

| リスク | 影響 | 緩和 |
|---|---|---|
| ハイバネート復元時にコンソールセッションも切れている | 再読込でサインイン画面に飛ぶ | `console-session-lifecycle` の無言再federationが働く。ハイバネート復元と期限切れ復帰は同じ経路に載せる |
| 色バーの注入がコンソールのレイアウトを壊す | 表示崩れ | `position: fixed` + 高い z-index で既存レイアウトに干渉しない形にする。実機で確認する |
| SPA遷移で色バーが消える | ガードレールが機能しない瞬間が生まれる | DOM 監視による再注入。監視のコストが問題になる場合は注入間隔を調整する |
| preload の責務が増え続ける | サンドボックスの意味が薄れる | preload の責務は色バー注入と MFA 入力補助の**2つで打ち止め**。これ以上増やさない |
| `tabs.json` に秘密情報が混入 | 平文での漏洩 | D7 の方針を明文化し、保存前に federation URL を除外する |
| ハイバネート時間が短すぎて再読込が頻発 | 摩擦が増える | 既定30分。設定可能にする |
| ショートカットが AWS コンソール自身のショートカットと衝突 | コンソールの操作性が落ちる | 実機で確認。衝突するものは割当を変更する |

## Migration Plan

`electron-app-shell` の `TabManager` にハイバネート状態を追加する。既存のデタッチ機構は変更せず、状態モデルを拡張する形にする。

`config.json` は `sso-account-directory` で既に導入済みのため、スキーマを拡張する。`tabs.json` は本 change で新設する。

## Open Questions

- 色バーの再注入方式 — `MutationObserver` か定期チェックか。コンソールのSPA挙動を実機で見て決める
- ハイバネートの粒度 — アカウント単位で一括ハイバネートする機能も要るか
- `Cmd+Opt+R` のリージョン切替で、コンソールURLのリージョン部分をどう書き換えるか（サービスごとにURL形式が異なる）
- コマンドパレットのサービス一覧をどこから供給するか（静的リストか、コンソールから取得するか）
