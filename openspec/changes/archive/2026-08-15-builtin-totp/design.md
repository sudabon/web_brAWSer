## Context

`sso-account-directory` により、MFA コードが必要なのは SSO セッション確立時（1日1回程度）だけになった。しかしそのコードの供給元は現在も Chrome 拡張 Authenticator であり、ブラウザを本アプリへ分離した時点で使えなくなる。

本 change はこの穴を塞ぐ。ただし、**このアプリは第1要素（コンソールを開く手段）と第2要素（TOTPシード）を同一プロセスに同居させる**という、セキュリティ上重大なトレードオフを伴う。設計の大半はこのトレードオフの緩和に費やされる。

## Goals / Non-Goals

**Goals:**

- TOTP シードをアプリ内に安全に保管し、コードを生成・表示する
- 既存の Authenticator からの移行経路を用意する
- Identity Center サインインページでの入力の手数を減らす
- 第1要素と第2要素の同居によるリスクを、暗号化・Touch ID ゲート・運用方針で緩和する

**Non-Goals:**

- **パスワードマネージャ機能**。TOTP のみを扱い、パスワードは扱わない
- **自動入力**。汎用ブラウザの自動入力機構は作らない。挿入は Identity Center サインインページ限定・ワンクリック・自動送信なし
- `otpauth-migration://offline?data=<base64 protobuf>`（Google Authenticator エクスポート形式）。protobuf デコードが必要で優先度が低い
- FIDO2 / パスキー対応。WebView 内の WebAuthn は挙動が不安定で本アプリのフローと相性が悪い

## Decisions

### D1: 自動入力を作らず、Identity Center サインインページ限定のワンクリック挿入に留める

汎用ブラウザで自動入力を作ると、対象サイトの UI 変更に追従し続けるコストが発生し、誤入力・誤送信のリスクも負う。

本アプリの対象は **Identity Center サインインページ1つだけ**である。ページが1つなら DOM 検出のロジックは単純で、AWS 側の UI 変更への追従コストも小さい。ここが「汎用ブラウザで自動入力を作る」場合との決定的な差であり、この差があるから実装する価値がある。

自動送信はしない。送信の判断は利用者に残す。

### D2: 保管は `safeStorage` + Touch ID の二段構え

`safeStorage.encryptString()` は macOS では Keychain 由来の鍵を使う。これだけでは「アプリが動いていれば誰でも読める」ため、起動後の初回参照時に `systemPreferences.promptTouchID()` でゲートし、スリープ復帰で再ロックする。

復号済みシードはメモリ上にのみ持つ。ディスクへ書き戻すのはインポート時の暗号化保存のみ。

### D3: 高権限シードを持ち込まない運用方針を仕様に含める

技術的緩和には限界がある。アプリまたはユーザーディレクトリが侵害された時点で、MFA は防御として機能しなくなる。

したがって**ルートアカウントとブレークグラス用のシードは本アプリに入れない**。別デバイスまたは 1Password 等に残す。これは実装ではなく運用方針だが、インポート画面に明示することで仕様として担保する。

### D4: QR 取り込みは `screencapture -i` + `zxing-wasm`

macOS では画面上の QR を範囲選択で取り込むのが最も実用的である。`child_process` から `screencapture -i` を呼び、生成された PNG をデコードする。

デコーダは `jsQR` ではなく **`zxing-wasm`** を使う。低解像度・傾きに強く、画面キャプチャという不安定な入力に対して成功率が高い。

一時 PNG はデコード後ただちに削除する。TOTP シードを含む QR 画像がディスクに残るのは D2 の努力を無にする。

### D5: TOTP 生成は `otpauth` ライブラリを使う

RFC 6238 の自前実装は30行程度で書けるが、テスト済みのものを使う。認証系のコードで自前実装を選ぶ理由がない。

`algorithm` / `digits` / `period` は `otpauth://` URI で省略された場合、既定値 SHA1 / 6 / 30 を適用する。AWS Identity Center は標準的な TOTP なのでこれで足りるが、他サービスのシードも登録しうるため非標準パラメータも保持・使用できるようにする。

### D6: クリップボードは30秒で自動クリアする

コードをクリップボードに残し続けると、他アプリからの読み取りリスクが残る。30秒後にクリアする。ただし利用者がその間に別の内容をコピーした場合は、それを消してはならない。クリア前にクリップボードの現在値がコピーしたコードと一致するかを確認する。

### D7: preload の責務を増やさない

MFA 入力補助のために preload を使うが、`contextBridge.exposeInMainWorld` で公開する API は入力補助に必要な最小の IPC チャネルのみとする。`workspace-persistence-guardrails` の色バー注入と合わせて**preload の責務は2つで打ち止め**にする。ここを守らないとサンドボックスの意味が薄れる。

### D8: Touch ID が使えない環境は確認ダイアログで解錠する

`systemPreferences.canPromptTouchID()` が true のときは Touch ID を要求する。非搭載機や外部キーボード運用では、別パスワードを新設せず、確認ダイアログ（解錠 / キャンセル）にフォールバックする。Keychain 由来の `safeStorage` 暗号化は維持する。ゲートなしにはしない。

スリープ復帰の再ロックは `powerMonitor` の `resume` で行う。

Authenticator のバックアップは、拡張のエクスポート形式（ハッシュキーの JSON マップ、`secret` / `issuer` / `account` / `type`）と、公式の行区切り `otpauth://` URI テキストの両方を受け付ける。暗号化バックアップは拒否する。

## Risks / Trade-offs

| リスク | 影響 | 緩和 |
|---|---|---|
| **第1要素と第2要素の同居** | アプリまたはユーザーディレクトリの侵害で MFA が無効化される | D2（`safeStorage` + Touch ID）、D3（高権限シードを入れない）、`packaging-and-url-handoff` での署名。**このリスクは完全には消せない。受容する判断を明示する** |
| 未署名だと Keychain プロンプトが毎回出る | 常用時の摩擦 | `packaging-and-url-handoff` で署名。開発中は許容 |
| QR 画像の一時ファイルが残る | シード漏洩 | デコード後に即削除。削除失敗時はエラーとして扱う |
| Identity Center の UI 変更で入力欄検出が壊れる | 入力補助が効かなくなる | 対象が1ページのみなので追従コストは小さい。検出失敗時はオーバーレイを出さないだけで、手入力にフォールバックできる |
| クリップボード経由でのコード漏洩 | 他アプリからの読み取り | D6 の30秒自動クリア |
| Identity Center が FIDO2 必須設定 | TOTP が使えず本 change が無意味になる | `verify-sso-federation-spike` の確認項目。着手時点で解消している前提 |
| `screencapture` が macOS 依存 | 他OSで動かない | 他OS対応は非目標。他OS では画像D&D / URI貼り付け / 直接入力で代替できる設計にする |

## Migration Plan

Chrome 拡張 Authenticator からの移行は、拡張のバックアップ JSON をインポートする経路で行う（初回のみ）。移行後も拡張側のシードは削除せず、本アプリが常用に耐えると確認できるまで並行運用する。

ルートアカウント・ブレークグラス用のシードは移行対象から**除外する**（D3）。

## Open Questions

- なし。Touch ID 非搭載時は確認ダイアログ（D8）。スリープ復帰は `powerMonitor` の `resume`。Authenticator JSON は拡張のエクスポート形式と otpauth URI リストを実装時に確認した。
